## UI復旧

- globals.cssをUI復元基準の完全版へ戻す
- 受注後契約板用スタイルを末尾へ統合

## CSS上書き事故の原因

- GitHub MCPのpush_filesは、既存ファイルへの追記ではなく、指定ファイル全体を置き換える
- globals.cssへ一部のスタイルだけを渡すと、既存の全CSSが消失する
- Fleet・契約詳細・受注後契約板など、UI変更のたびにglobals.cssへ追記しようとして上書き事故が発生した
- globals.cssに全UIスタイルが集中しているため、一部分だけ更新する運用が事故の再発につながった

## 復旧手順

1. 正常だったコミットのglobals.cssを取得する
2. 現行の機能追加用CSSを失わないよう確認する
3. 正常版CSSを復元する
4. 新規スタイルは既存CSSの末尾へ統合する
5. 全文をpush_filesへ渡してPushする
6. Vercelプレビューで契約板・Fleet・契約詳細を確認する

## 今後のUI変更ルール

- 現在のスタイルをUI基準として保持し続ける
- 既存のglobals.cssは、変更前に必ず全文を取得する
- globals.cssを更新する場合は、既存CSSをすべて保持した完全版を渡す
- 新規スタイルは既存CSSの末尾へ統合する
- 既存クラスのスタイルを安易に削除・置換しない
- 新機能・新ページ追加時も、既存の420px幅・16px余白・8pxカード間隔・14pxカード内余白・12px角丸を参照する
- 新しいページもpage/page-body/card構造と既存カード基準を利用する
- CSSの大規模変更を行う場合は、先にCSSを機能別へ分割することを検討する
